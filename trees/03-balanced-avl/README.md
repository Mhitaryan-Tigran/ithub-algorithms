# Сбалансированные деревья поиска

Обычное BST при неудачном порядке вставки вырождается в список: если вставлять ключи по возрастанию, высота равна n, и поиск, вставка, удаление идут за O(n). Сбалансированные деревья после каждого изменения восстанавливают форму и держат высоту O(log n).

| Вид дерева | Как держит баланс | Преимущества | Недостатки | Где применяется |
|---|---|---|---|---|
| AVL-дерево | высоты поддеревьев любого узла отличаются не больше чем на 1, нарушение чинится поворотами | самое низкое из распространённых деревьев (высота ≤ 1,44 log n), поэтому самый быстрый поиск | при вставке и удалении больше поворотов, чем у красно-чёрного, в узле хранится высота | словари с частым чтением и редкой записью, базы данных в памяти |
| Красно-чёрное дерево | узлы раскрашены, на любом пути от корня до листа одинаковое число чёрных узлов, красный не идёт за красным | вставка и удаление делают не больше 2–3 поворотов, предсказуемая скорость записи | дерево выше, чем AVL (до 2 log n), код удаления сложный | `std::map` в C++, `TreeMap` в Java, планировщик CFS в Linux |
| B-дерево и B+-дерево | в узле много ключей (сотни), все листья на одной глубине | мало уровней, значит мало чтений с диска, B+ удобно для диапазонных запросов | для данных в памяти сложнее и медленнее бинарных деревьев | индексы PostgreSQL и MySQL, файловые системы NTFS, ext4, APFS |
| Splay-дерево | каждый найденный узел поворотами поднимается в корень | без дополнительных полей, часто запрашиваемые ключи находятся почти мгновенно | одна операция может стоить O(n), амортизированно O(log n), чтение меняет дерево | кэши, сетевые таблицы маршрутов |
| Декартово дерево (treap) | ключ упорядочен как в BST, случайный приоритет как в куче | простой код, легко делить и склеивать деревья | баланс только в среднем, зависит от случайности | олимпиадные задачи, неявные ключи для массивов с вставками в середину |

## Реализация

В `avl.py` реализовано AVL-дерево: вставка и удаление с четырьмя случаями поворотов (LL, RR, LR, RL), проверка инварианта и сравнение с обычным BST.

```
python3 avl.py
```

При вставке ключей 1..15 по возрастанию обычное BST получает высоту 15, AVL-дерево — высоту 4, то есть ровно ⌈log₂ 16⌉. Случайный тест на 2000 операций вставки и удаления проверяет, что после каждой операции баланс всех узлов не превышает 1, а симметричный обход совпадает с отсортированным множеством ключей.
