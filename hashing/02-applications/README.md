# Применение хеш-функций на практике

Каждый пример запускается и проверяется в `python3 applications.py`.

| № | Где применяется | Какая функция | Какое свойство хеша используется |
|---|---|---|---|
| 1 | Проверка целостности скачанного файла: на сайте публикуют SHA-256 образа, пользователь сверяет свой | SHA-256 | Лавинный эффект: изменение одного байта меняет весь хеш |
| 2 | Поиск дубликатов файлов и дедупликация в бэкапах и облачных хранилищах: сравниваются хеши, а не файлы целиком | SHA-256 | Одинаковое содержимое даёт одинаковый хеш, разное — практически никогда |
| 3 | Git хранит каждый файл и коммит под именем, равным хешу содержимого («адресация по содержимому») | SHA-1 от `blob <длина>\0<данные>`, в новых репозиториях SHA-256 | Детерминированность: id в программе совпал с `git hash-object` |
| 4 | Хранение паролей: в базе лежат соль и медленный хеш, а не сам пароль | scrypt, bcrypt, Argon2 | Необратимость, соль защищает от радужных таблиц, медленность — от перебора |
| 5 | Подпись webhook-запросов и API (Stripe, GitHub, Telegram) | HMAC-SHA256 | Без секретного ключа нельзя подделать подпись к изменённому телу |
| 6 | Шардирование: по хешу ключа выбирается сервер базы данных или кэша | MD5 / MurmurHash по модулю числа серверов, consistent hashing | Равномерное распределение ключей |
| 7 | Фильтр Блума: браузер проверяет, встречался ли URL, без хранения всех URL | k хеш-функций в битовом массиве | Быстрая проверка «точно нет / возможно да» с малым расходом памяти |
| 8 | Хеш-таблицы: `dict` и `set` в Python, `HashMap` в Java, индексы hash в PostgreSQL | SipHash и другие некриптографические | Поиск, вставка и удаление за O(1) в среднем |
| 9 | Блокчейн: каждый блок содержит хеш предыдущего, майнинг ищет хеш с нулями в начале | SHA-256 | Изменение старого блока ломает всю цепочку |
| 10 | Электронная подпись документа: подписывается не документ, а его хеш | SHA-256, ГОСТ Р 34.11-2012 «Стрибог» | Короткий хеш фиксированной длины однозначно представляет документ |
