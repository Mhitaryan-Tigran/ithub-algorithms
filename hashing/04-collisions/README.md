# Способы разрешения коллизий

Коллизия — два разных ключа получили одинаковый адрес. Её нельзя исключить (ключей больше, чем ячеек), её можно только разрешить.

| Способ | Идея | Плюсы | Минусы | Где используется |
|---|---|---|---|---|
| Метод цепочек | В ячейке хранится список всех ключей с этим адресом | Простое удаление, работает и при α > 1 | Лишняя память на указатели, промахи кэша процессора | `HashMap` в Java, `unordered_map` в C++ |
| Цепочки с деревом | Длинная цепочка превращается в сбалансированное дерево | Худший случай O(log n) вместо O(n) | Сложнее код | `HashMap` в Java 8+ |
| Линейное пробирование | Следующая ячейка: h + 1, h + 2, … | Лучшая работа с кэшем | Первичная кластеризация | Rust `HashMap` (на основе SwissTable), LLVM |
| Квадратичное пробирование | h + 1², h + 2², … | Нет первичной кластеризации | Вторичная кластеризация, обходит не все ячейки | — |
| Двойное хеширование | Шаг h₂(k) зависит от ключа | Почти равномерные последовательности | Две хеш-функции, хуже кэш | — |
| **Кукушкино хеширование** | Две таблицы и две функции. Ключ лежит в одной из двух ячеек. Если обе заняты, ключ выталкивает жильца, тот переезжает во вторую свою ячейку, и так далее | Поиск и удаление — **не больше 2 проверок** в худшем случае | Вставка может зациклиться — тогда таблица перестраивается, заполнение до ~50% | Сетевое оборудование, кэши, фильтры Cuckoo |
| **Хеширование Робин Гуда** | Линейное пробирование, но ключ, ушедший дальше от «дома», забирает ячейку у ключа, который ближе к своему «дому» | Выравнивает длину поиска: худший случай резко меньше; поиск отсутствующего ключа обрывается раньше | Сложнее удаление (сдвиг назад) | Rust до 1.36, многие БД |
| Перехеширование | При α выше порога таблица увеличивается, ключи раскладываются заново | Держит коллизии редкими | Разовая пауза O(n) | Все практические таблицы |

## Код

`python3 collisions.py` — реализации и проверки:

1. `CuckooHashTable` — вставка с выталкиванием (лог показывает каждое перемещение), поиск за 2 проверки, перестройка при зацикливании.
2. `RobinHoodHashTable` — вставка с обменом по расстоянию до «дома», поиск с ранним выходом, удаление со сдвигом назад без маркеров DELETED.
3. Сравнение на 85 случайных ключах в таблице из 101 ячейки: среднее число проверок при успешном поиске одинаковое (2,52), но худший случай у линейного пробирования 17, у Робин Гуда 6.

Случайный тест из 50 серий по 150 операций проверяет, что обе таблицы всегда содержат ровно те ключи, которые должны.
